4. T1 三大核心问题修补（IMPLEMENTATION-PLAN.md §7 三短板）
────────────────────────────────────────────────────────────────────────────────

| 短板 | E# | 修补实现 |
|---|---|---|
| 短板1：M 单元是 stub（仅校验存在+版本；命名/ID 转义/跨协议唯一性兜不住） | E1 | 新增独立命令 m-check；命名规范 `/^[A-Z]+_\w+$/` + 跨协议 ID 唯一性 + 附属实体归属 + 旧字符禁用 + ID 转义前置；specifier pre-check 复用同一规则集 |
| 短板2：specs.json 是"接口目录"而非"接口契约"（inputs/outputs 仅 name+type+description） | E2 | specs.json 升级为 SpecsEnvelope（含 schemaVersion）；每个接口有 requestSchema/responseSchema/preconditions/postconditions；schemaKind 标记（structured/legacy-stub/description-only）；verify 偏差对比从状态 ID 扩到字段级（field_mismatch） |
| 短板3：人工从零写 bindings.yaml（hsk-ng 18 单手工补 40 路由） | E3 | 新增 derive-bindings：specs.json → bindings.skeleton.yaml（method/path/params 机械推导）；mergeBindings(skeleton, manual) 让人工只填 baseUrl/headers/authConfig/stateMap；生成率 100% |
